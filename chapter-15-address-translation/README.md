# OSTEP Chapter 15: Address Translation

Homework for [OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/), chapter 15 ("Mechanism: Address Translation").
All runs use `relocation.py` from [ostep-homework](https://github.com/remzi-arpacidusseau/ostep-homework) (`vm-mechanism/`).
The simulator and its flags are described in the [homework README](https://github.com/remzi-arpacidusseau/ostep-homework/blob/master/vm-mechanism/README.md).

The rule behind every answer:

```
if virtual address >= limit:  segmentation violation
else:                         physical address = base + virtual address
```

Defaults of the simulator: address space 1k (virtual addresses 0 to 1023), physical memory 16k (16384 bytes).

```
  VA  0: 0x0000017a (decimal:  378) --> SEGMENTATION VIOLATION
  VA  1: 0x0000026a (decimal:  618) --> SEGMENTATION VIOLATION
  VA  2: 0x00000280 (decimal:  640) --> SEGMENTATION VIOLATION
  VA  3: 0x00000043 (decimal:   67) --> VALID: 0x00002317 (decimal: 8983)
  VA  4: 0x0000000d (decimal:   13) --> VALID: 0x000022e1 (decimal: 8929)
```

**Answer:** an address is valid exactly when it is smaller than the limit. The physical address is then base plus virtual address.

| Seed | Base | Limit | Valid addresses | Translation |
|---|---|---|---|---|
| 1 | 13884 | 290 | 261 | 13884 + 261 = 14145 |
| 2 | 15529 | 500 | 57, 86 | 15586, 15615 |
| 3 | 8916 | 316 | 67, 13 | 8983, 8929 |

Everything else is at or above the limit and raises a segmentation violation. With limits between 290 and 500 only about a third to a half of the 1k address space is valid, which is why most of the random addresses fail.

## 3. Run with these flags: -s 1 -n 10 -l 100. What is the maximum value that bounds can be set to, such that the address space still fits into physical memory in its entirety?

```sh
./relocation.py -s 1 -n 10 -l 100 -c
```

```
Base-and-Bounds register information:

  Base   : 0x00000899 (decimal 2201)
  Limit  : 100

Virtual Address Trace
  VA  0: 0x00000363 (decimal:  867) --> SEGMENTATION VIOLATION
  VA  1: 0x0000030e (decimal:  782) --> SEGMENTATION VIOLATION
  VA  2: 0x00000105 (decimal:  261) --> SEGMENTATION VIOLATION
  VA  3: 0x000001fb (decimal:  507) --> SEGMENTATION VIOLATION
  VA  4: 0x000001cc (decimal:  460) --> SEGMENTATION VIOLATION
  VA  5: 0x0000029b (decimal:  667) --> SEGMENTATION VIOLATION
  VA  6: 0x00000327 (decimal:  807) --> SEGMENTATION VIOLATION
  VA  7: 0x00000060 (decimal:   96) --> VALID: 0x000008f9 (decimal: 2297)
  VA  8: 0x0000001d (decimal:   29) --> VALID: 0x000008b6 (decimal: 2230)
  VA  9: 0x00000357 (decimal:  855) --> SEGMENTATION VIOLATION
```

The base has to be pinned with `-b` for the boundary test. If only `-l` is raised, the simulator simply draws a different base that still fits.

```sh
./relocation.py -s 1 -n 10 -b 2201 -l 14183 -c
```

```
  Base   : 0x00000899 (decimal 2201)
  Limit  : 14183
  ...
  VA  8: 0x00000060 (decimal:   96) --> VALID: 0x000008f9 (decimal: 2297)
  VA  9: 0x0000001d (decimal:   29) --> VALID: 0x000008b6 (decimal: 2230)
```

```sh
./relocation.py -s 1 -n 10 -b 2201 -l 14184 -c
```

```
  Base   : 0x00000899 (decimal 2201)
  Limit  : 14184

Error: address space does not fit into physical memory with those base/bounds values.
Base + Limit: 16385   Psize: 16384
```

**Answer:** the condition is `base + limit <= physical memory size`, so the maximum limit is 16384 minus base. With the base of this run (2201) that is 16384 - 2201 = 14183. The last valid virtual address 14182 then maps to physical address 16383, the last byte of memory.

The same condition read the other way round: with the limit fixed at 100, the highest possible base is 16384 - 100 = 16284 (`-b 16284` runs, `-b 16285` gives the same error). The absolute maximum for the limit is 16384, with base 0.

## 4. Run some of the same problems above, but with larger address spaces (-a) and physical memories (-p).

```sh
./relocation.py -s 1 -a 32m -p 1g -c
```

```
ARG seed 1
ARG address space size 32m
ARG phys mem size 1g

Base-and-Bounds register information:

  Base   : 0x363c5ab6 (decimal 909925046)
  Limit  : 9515736

Virtual Address Trace
  VA  0: 0x01870d77 (decimal: 25628023) --> SEGMENTATION VIOLATION
  VA  1: 0x00829868 (decimal: 8558696) --> VALID: 0x36bef31e (decimal: 918483742)
  VA  2: 0x00fda9aa (decimal: 16624042) --> SEGMENTATION VIOLATION
  VA  3: 0x00e623b1 (decimal: 15082417) --> SEGMENTATION VIOLATION
  VA  4: 0x014d9d98 (decimal: 21863832) --> SEGMENTATION VIOLATION
```

**Answer:** nothing changes except the size of the numbers. It is the same pattern as seed 1 in exercise 1 (only VA 1 is valid), because the same random fractions are scaled to the larger sizes. The one valid address translates to 909925046 + 8558696 = 918483742.

Translation stays one comparison and one addition no matter how large the address space is. The hardware needs two registers per process and no table. That is the strength of base and bounds. The weakness is that the whole address space must sit in physical memory as one contiguous block.
